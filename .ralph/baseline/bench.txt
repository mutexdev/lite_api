# Benchmark baseline — US-005
#
# Captured on branch ralph/postman-switchable-v2 after US-003's linter cleanup.
# Command:
#   go test -bench=. -benchmem -run='^$' -benchtime=10x .
#
# -benchtime=10x, not the 1s default: BenchmarkPersistLocked serialises ~37 MB and
# writes it to disk per iteration, so the default would run for minutes and thrash
# the disk without adding signal.
#
# ---------------------------------------------------------------------------
# !! -benchtime=10x IS ONLY VALID FOR SLOW BENCHMARKS. Read this before judging
# any Phase 1 story against these numbers.
#
# 10 iterations of a sub-microsecond function is ~7 us of measured work, so one
# scheduling hiccup moves the result by 2x. Demonstrated on US-023: fifteen 10x
# samples of Interpolate/vars=50 after the rewrite ranged 708..1554 ns/op
# (median 1054), while the steady state (-benchtime=200000x -count=3) is a tight
# 647..669 ns/op. The 10x spread straddles the story's own <=1458 ns/op
# acceptance threshold, so a passing change could be recorded as a failure, or a
# regression missed, on noise alone.
#
# The ORIGINAL numbers below are trustworthy at 10x because the original code was
# slow enough (14.6 us at vars=50) for 10 iterations to be representative. That
# stops being true the moment a story makes something fast.
#
# RULE: compare slow benchmarks (PersistLocked, WriteCollectionFilesLocked,
# NewScriptRuntimeWithMeta) at 10x; compare fast ones (Interpolate, ExecuteHTTP)
# at -benchtime=200000x -count=3 and quote the median. Applying §5.1's ">5%
# regression" gate to a 10x sample of a fast benchmark is not a measurement.
# ---------------------------------------------------------------------------
#
# ---------------------------------------------------------------------------
# COMPARISONS MUST BE SAME-HOST.
# improvement_v2.md §5.1 prescribes "no regression >5% on any benchmark". That gate
# is only meaningful against numbers captured on this machine. A laptop baseline
# compared against a CI runner will produce both false failures and false passes.
# Re-capture on the comparison host before judging any Phase 1 story.

# ===========================================================================
# ACCEPTED REGRESSION — BenchmarkPersistLockedSmallState, US-012
# ===========================================================================
#
# 541,867 -> ~5,537,842 ns/op (+920%). This is NOT a defect and must not be
# "fixed" by a later story without reading this.
#
# Cause: writeFileAtomic fsyncs the temp file before os.Rename. Measured on this
# APFS volume each fsync costs ~4.7 ms; with the Sync() removed and nothing else
# changed the same benchmark runs at ~400,058 ns/op, i.e. FASTER than the
# original. The cost is entirely durability, not overhead.
#
# Accepted deliberately:
#   * The pre-US-012 code had neither fsync nor atomic rename — a crash could
#     leave a truncated state.json. This is strictly more durable than what
#     shipped.
#   * Dropping the fsync would keep SIGKILL survival (rename alone gives that)
#     but lose durability against power loss or kernel panic. LiteAPI is
#     local-first; the user's collections and workspace state are the product.
#   * Frequency inverted. The writer ran ~20x/s in the FOREGROUND under the
#     global exclusive mutex (once per keystroke); it now runs at most 4x/s in
#     the BACKGROUND. Total fsync cost ~19 ms/s of background I/O against
#     ~11 ms/s of foreground I/O before.
#
# The keystroke path is what actually regressed or improved for a user, and it
# is now measured by BenchmarkMarkDirty, not by BenchmarkPersistLocked:
#
#   BenchmarkMarkDirty   573,933 ns/op   3,354 B/op   27 allocs/op
#   (was BenchmarkPersistLocked 225,684,108 ns/op  221,066,295 B/op)
#   -> 393x faster, 65,900x fewer bytes per typed character.
#
# ===========================================================================
# What these numbers establish
# ===========================================================================
#
# BenchmarkPersistLocked — 225.7 ms/op, 221 MB allocated, per call.
#   This is the keystroke path. UpdateRequest fires persistLocked on every
#   keystroke (improvement_v2.md §2.1.B), so on a 500-request workspace a single
#   character typed costs ~226 ms of blocking work under the global exclusive
#   mutex and allocates 221 MB.
#
#   Against BenchmarkPersistLockedSmallState (0.54 ms, 248 KB) the split is stark:
#   fixed overhead — MkdirAll, secrets, OAuth2 credential storage — is 0.24% of the
#   time and 0.11% of the allocation. Everything else is the state payload itself.
#   So the cost is not incidental; it scales with cached response bodies, exactly
#   as §2.1.B predicts.
#
#   221 MB allocated for a ~37 MB fixture is ~6x amplification, from
#   json.MarshalIndent's indentation, string escaping and buffer growth. US-012's
#   switch to json.Marshal attacks part of this; US-009 (moving bodies out of
#   AppState) attacks the rest.
#
#   Gates: US-009, US-012, US-013.
#
# BenchmarkWriteCollectionFilesLocked — 4.16 ms/op for ONE 50-request collection.
#   Saving a single request currently rewrites the whole collection. Gates US-015.
#
# BenchmarkInterpolate — superlinear in variable count, as the up-to-8-pass x
#   every-var x ReplaceAll implementation implies:
#       10 vars ->  6.2 us
#       50 vars -> 14.6 us   (5x the vars, 2.4x the time)
#      200 vars -> 92.9 us   (4x more vars again, 6.4x the time)
#   The vars=50 case is the one US-023 is graded on (">=10x at 50 vars"), i.e. a
#   target of <=1.46 us/op. Note interpolate runs per header, per param and per
#   body segment, so this multiplies out per request.
#
# BenchmarkNewScriptRuntimeWithMeta — 5.47 ms/op, 4.0 MB, 66,119 allocs.
#   That is the cost of RunString'ing 25 JS shims with no *goja.Program cache.
#   §2.1 notes this runs up to 4x per request, so ~22 ms and ~264k allocations of
#   pure setup before a single line of user script executes.
#   US-018 targets >=5x here, i.e. <=1.09 ms/op.
#
# BenchmarkExecuteHTTP — 310 us/op against a loopback httptest server, including
#   transport setup. Hermetic by design: no external process. The proxy/mTLS
#   connection-reuse proof belongs to US-016 (one TCP connection over N sends).
#
# ===========================================================================
# Caveats
# ===========================================================================
#
# * b.N loops, not Go 1.24's b.Loop(). b.Loop() additionally prevents dead-code
#   elimination of the benchmark body. Switching is a real improvement but would
#   invalidate comparability with these numbers, so it must happen BEFORE Phase 1
#   starts or not at all. Logged in .ralph/backlog.md.
# * BenchmarkWriteCollectionFilesLocked performs one untimed warm-up call. The
#   collection is a shallow copy whose Items slice is shared, and
#   ensureRequestFilePaths rewrites every FilePath on first call; without the
#   warm-up, iteration 1 does work iterations 2+ skip and skews a 10x run by ~10%.
# * persistLocked branches to persistWorkspaceRuntimeLocked when
#   a.workspaceRuntime != nil. NewAppWithDir leaves it nil, so these numbers cover
#   the main path. Re-check if US-012 changes that branch.
