# ===========================================================================
# What these numbers establish
# ===========================================================================
#
# BenchmarkPersistLocked — 225.7 ms/op, 221 MB allocated, per call.
#   This is the keystroke path. UpdateRequest fires persistLocked on every
#   keystroke (improvement_v2.md §2.1.B), so on a 500-request workspace a single
#   character typed costs ~226 ms of blocking work under the global exclusive
#   mutex and allocates 221 MB.
#
#   Against BenchmarkPersistLockedSmallState (0.54 ms, 248 KB) the split is stark:
#   fixed overhead — MkdirAll, secrets, OAuth2 credential storage — is 0.24% of the
#   time and 0.11% of the allocation. Everything else is the state payload itself.
#   So the cost is not incidental; it scales with cached response bodies, exactly
#   as §2.1.B predicts.
#
#   221 MB allocated for a ~37 MB fixture is ~6x amplification, from
#   json.MarshalIndent's indentation, string escaping and buffer growth. US-012's
#   switch to json.Marshal attacks part of this; US-009 (moving bodies out of
#   AppState) attacks the rest.
#
#   Gates: US-009, US-012, US-013.
#
# BenchmarkWriteCollectionFilesLocked — 4.16 ms/op for ONE 50-request collection.
#   Saving a single request currently rewrites the whole collection. Gates US-015.
#
# BenchmarkInterpolate — superlinear in variable count, as the up-to-8-pass x
#   every-var x ReplaceAll implementation implies:
#       10 vars ->  6.2 us
#       50 vars -> 14.6 us   (5x the vars, 2.4x the time)
#      200 vars -> 92.9 us   (4x more vars again, 6.4x the time)
#   The vars=50 case is the one US-023 is graded on (">=10x at 50 vars"), i.e. a
#   target of <=1.46 us/op. Note interpolate runs per header, per param and per
#   body segment, so this multiplies out per request.
#
# BenchmarkNewScriptRuntimeWithMeta — 5.47 ms/op, 4.0 MB, 66,119 allocs.
#   That is the cost of RunString'ing 25 JS shims with no *goja.Program cache.
#   §2.1 notes this runs up to 4x per request, so ~22 ms and ~264k allocations of
#   pure setup before a single line of user script executes.
#   US-018 targets >=5x here, i.e. <=1.09 ms/op.
#
# BenchmarkExecuteHTTP — 310 us/op against a loopback httptest server, including
#   transport setup. Hermetic by design: no external process. The proxy/mTLS
#   connection-reuse proof belongs to US-016 (one TCP connection over N sends).
#
# ===========================================================================
# Caveats
# ===========================================================================
#
# * b.N loops, not Go 1.24's b.Loop(). b.Loop() additionally prevents dead-code
#   elimination of the benchmark body. Switching is a real improvement but would
#   invalidate comparability with these numbers, so it must happen BEFORE Phase 1
#   starts or not at all. Logged in .ralph/backlog.md.
# * BenchmarkWriteCollectionFilesLocked performs one untimed warm-up call. The
#   collection is a shallow copy whose Items slice is shared, and
#   ensureRequestFilePaths rewrites every FilePath on first call; without the
#   warm-up, iteration 1 does work iterations 2+ skip and skews a 10x run by ~10%.
# * persistLocked branches to persistWorkspaceRuntimeLocked when
#   a.workspaceRuntime != nil. NewAppWithDir leaves it nil, so these numbers cover
#   the main path. Re-check if US-012 changes that branch.
