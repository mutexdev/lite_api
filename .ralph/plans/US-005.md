## Benchmark set

Each is written so the Phase 1 story that rewrites it has a directly comparable number.

| Benchmark | Measures | Phase 1 story it gates |
|---|---|---|
| `BenchmarkPersistLocked` | full-state `MarshalIndent` + synchronous `os.WriteFile` on the 500-request fixture | US-012 (async coalesced persistence), US-009 (body store) |
| `BenchmarkPersistLockedSmallState` | same on a trivial state — isolates fixed overhead from payload cost | US-012 |
| `BenchmarkWriteCollectionFilesLocked` | rewriting an entire 50-request collection to disk | US-015 (dirty-set writes) |
| `BenchmarkInterpolate/vars=10\|50\|200` | the up-to-8-pass × every-var × `ReplaceAll` scan | US-023 (single-pass, target ≥10× at 50 vars) |
| `BenchmarkNewScriptRuntimeWithMeta` | `RunString` of 25 JS shims with no program cache | US-018 (goja program cache, target ≥5×), US-019 (runtime pool) |
| `BenchmarkExecuteHTTP` | one full request against a loopback server, incl. transport setup | US-016/US-017 (transport cache), US-011 (bounded reads) |

`BenchmarkExecuteHTTP` uses an `httptest.Server` on loopback, **not** `qa/platformfixture`, so it
has no external process dependency and stays hermetic in CI. A proxy/mTLS variant belongs to US-016,
whose acceptance criterion is explicitly "one TCP connection over N sequential sends".

## Method

- `b.ReportAllocs()` on every benchmark — allocation counts are the honest signal for US-009 and
  US-012; wall-clock alone is noisy under a loaded CI runner.
- `b.ResetTimer()` after fixture construction. Building a 40 MB fixture inside the timed loop would
  swamp the measurement.
- Fixture built **once** per benchmark via `newLargeWorkspaceApp(b.TempDir(), opts)` (US-006), not
  per iteration.
- `persistLocked` requires the caller to hold `a.mu` (the `Locked` suffix is the convention in this
  file). The benchmark must take the lock explicitly, matching real call sites.

## Baseline capture

```sh
go test -bench=. -benchmem -run=^$ -benchtime=10x ./... | tee .ralph/baseline/bench.txt
```

`-benchtime=10x` rather than the default 1s: `BenchmarkPersistLocked` serialises tens of MB and
writes to disk per iteration, so a 1s default would take minutes and thrash the disk. A fixed low
iteration count keeps the suite usable as a gate. Record the machine and Go version in the file —
absolute numbers are only comparable on the same host.

## Risks

- **`go test -bench=. ./...` also runs benchmarks in `qa/` subpackages.** Scope with `-run=^$` so no
  tests re-run, and be explicit that the baseline file covers the root package.
- `executeHTTP` has a 7-argument signature including two nilable callbacks (`onFailState`,
  `recordTimeline`). Passing `nil` may panic if the function does not guard. Verify before
  benchmarking; if it does not guard, pass a no-op `recordTimeline` rather than "fixing" `app.go`
  under this story.
- The `>5% regression` gate in §5.1 is meaningless against a baseline captured on a developer laptop
  and compared on a CI runner. State plainly in `bench.txt` that comparisons must be same-host, and
  treat cross-host numbers as indicative only.
