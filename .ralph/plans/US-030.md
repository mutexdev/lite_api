## THE LANDMINE — read before writing any key

Svelte throws at RUNTIME on duplicate keys, and neither `svelte-check`, `eslint`
nor `npm run build` can see it. A wrong key is strictly worse than no key.

**`devToolsNetworkColumnWidths = [80, 70, 180, 300, 110, 100, 80]`** — the value
`80` appears TWICE. Keying by value (`{#each … as width (width)}`) crashes the
DevTools network panel the moment it renders. This list is positional
configuration with no identity other than its position, so **index is the
correct key here**, notwithstanding the story's "keys are stable identities, not
array indices" rule — that rule is about lists of entities, and this is not one.

Apply the same test to every list before keying it: *can two elements ever be
equal?* If yes and there is no id, the key must be a composite, not the value.

HTTP headers are the other instance of this: `networkHeaderRows(...)` and
`filteredHeaders` yield `[name, value]` pairs, and repeated header names are
legal HTTP (`Set-Cookie` routinely repeats). Key those on
`` `${name}-${index}` ``, not `name`.

## Verification plan

1. `npx eslint . --rule '{"svelte/require-each-key":"error"}'` → 0.
2. Re-enable `svelte/require-each-key` as an error in `eslint.config.js` and
   delete the US-030 disable comment (US-004 recorded it as owned by this story).
3. `npm run check` 0/0, `npm run lint` 0, `npm test`, `npm run build`.
4. **Browser, non-negotiable** — the duplicate-key failure is runtime-only.
   Drive the app at `localhost:34115` (the Wails dev endpoint that serves the Go
   bindings; vite's 5173 does not) and render every keyed list at least once,
   watching the console for "Cannot have duplicate keys". The DevTools network
   panel, the header tables and the cookie groups are the highest-risk.
5. The story's real user-facing criterion — "input focus is not lost mid-edit
   when a list re-renders" — needs a focused input in a keyed list, a state
   change that re-renders it, then `document.activeElement` compared against the
   input. Assert that explicitly; it is the thing keys exist to fix.
